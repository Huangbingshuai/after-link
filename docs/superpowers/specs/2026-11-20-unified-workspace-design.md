# 掌柜智库统一工作台设计

## 意图

把当前分开的知识问答和文档导入前端整合成一个一致的工作台，让用户在同一页面体系内查资料、导入资料。界面要克制、清晰、有产品感，避免模板化渐变、装饰卡片和空泛宣传文案。

## 目标

- 以左侧工作区导航提供“知识问答”和“文档导入”两项功能，默认进入知识问答。
- 保留问答的 SSE 流式输出、会话历史、清除历史和任务进度。
- 澄清型答案在会话历史中只保存一次，刷新页面后不出现重复答复。
- 重复提问时，旧 SSE 流的清理不能移除同一会话中新建的流队列。
- 保留 PDF/Markdown 拖放与多文件导入、每个文件的状态、进度和可展开节点日志。
- 继续以两个本地 API 进程运行：问答 API 为 `127.0.0.1:8003`，导入 API 为 `127.0.0.1:8002`；统一页面从问答 API 提供，导入请求调用导入 API。
- 兼容桌面和窄屏，支持键盘焦点与减少动态效果偏好。

## 不做

- 不改变 LangGraph 工作流、数据库 schema、任务状态语义或现有 API 请求/响应结构。
- 不删除 `/chat.html`、`/import.html` 等旧入口。
- 不变更本地 MinIO 为云对象存储，也不重置已有数据库卷。
- 不在界面显示密钥或实现无关的系统配置面板。

## 反目标

- 不用大面积渐变、发光卡片、无语义统计数字或机器人口吻做“高级感”。
- 不把两个旧页面原样塞进 iframe，避免重复标题、重复导航和不一致的视觉层级。
- API 或服务不可用时，不显示虚假的“在线”状态；清楚指出失败的工作流。

## 端到端验证补充

用户授权使用 `doc/H3C LA2608室内无线网关 用户手册-6W100-整本手册.pdf` 完成一次 MinerU 导入，并用 DeepSeek 做少量问答。运行验证发现澄清型答案在 `node_item_name_confirm` 和 `node_answer_output` 两处写入 MongoDB；仅由最终答案节点负责保存助手答复，保留用户消息更新流程。

## 备选方案

1. **统一前端壳层，保留两个后端进程（选定）**：在问答服务上提供统一工作台页面；侧栏切换两个工作流，页面直接调用现有问答和导入接口。改动集中在前端与页面路由，现有任务流程不变。
2. **合并两个 FastAPI 应用**：前端和 API 可以同源，部署入口更集中，但会改变服务启动结构、导入顺序和生命周期，超出本次前端整合所需。
3. **首页链接到两个旧页面**：改动最少，但每个工作流仍是独立页面，也保留两套视觉，不满足统一工作台的目标。

## 布局与视觉提案

- 采用用户选定的 A 方案：稳定的左侧导航，主区域显示当前工作流；窄屏时将导航收为顶部切换控件。
- 视觉方向：像一套整理良好的产品手册档案室，而不是通用 AI 聊天模板。背景用浅矿物灰绿 `#F5F6F2`，主文字用石墨色 `#202724`，导航与强调色用深松针绿 `#294A3A`，辅色用灰叶绿 `#DDE7DC`，边框用 `#E0E5DE`，少量暖铜色 `#B48B57` 只标记状态或引用。
- 字体使用系统中文无衬线（PingFang SC / Microsoft YaHei）作为正文；衬线只在小型英文分区标签或来源编号中作轻微对照，不引入外部字体依赖。
- 布局以留白、对齐和细分隔线建立层次。问答回答突出正文和可核对的资料来源；导入页突出投放区域、文件状态和可展开处理日志。
- 记忆点是“来源索引”：回答中的手册/段落引用以窄边签条样式呈现，强调产品的知识可追溯属性。

## 约束与实现决定

- `8001` 已被另一应用占用，用户已确认本项目改用 `8003`；不可停止或覆盖占用 `8001` 的应用。
- 导入 API 固定在 `8002`，其 CORS 已允许浏览器跨端口请求；主页面调用导入 API 时应从当前主机名构造 `8002` 地址，不能保留旧页面中写死的 `8000`。
- 现有导入状态接口为 `GET /status/{task_id}`，字段是 `status`、`done_list`、`running_list`；导入上传使用 multipart 字段 `files`，响应给出 `task_ids`。
- 统一页面应明确显示当前工作流；导航切换不清空当前问答会话或仍在进行的导入任务。
- 旧 `/chat.html` 和 `/import.html` 路由保留并继续提供原页面；统一工作台使用问答服务根路径 `/`，避免改变已有链接行为。
- 页面内切换工作流时保留当前页面状态；刷新时，问答按现有方式通过本地会话 ID 重新加载历史，导入任务列表按现有方式在刷新后重置，不新增跨刷新任务恢复机制。
- MinerU 凭据当前为空，因为已提供的 Token 在 2026-09-05 到期。生成新 Token 后写入项目根目录 `.env` 的 `MINERU_API_TOKEN`。密钥不写入仓库或前端。
- BGE-M3 与 reranker 目录使用 `code/models/bge-m3` 和 `code/models/bge-reranker-large`；模型文件须实际存在后，导入向量化与问答重排才能完整工作。

以上两项旧路由与刷新行为是实现范围的明确决定：维持旧链接兼容和原有持久化边界，避免本次整合变成接口迁移或任务存储改造。

## 验收

- 打开 `http://127.0.0.1:8003/` 可以看到统一工作台，导航可切换两个工作流。
- 问答保持原 SSE、历史和清除历史行为；导入仍能上传 PDF/Markdown 并显示各自状态与处理日志。
- 同一会话连续提问时，每个 SSE 流继续接收其对应请求的事件。
- 8001 上的其他服务不受影响；应用 API 仅监听本机地址。
- 两种工作流至少在桌面和窄屏布局可用；错误和等待状态有明确说明。
